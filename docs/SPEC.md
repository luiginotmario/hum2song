# hum2song — implementation spec (for a coding agent)

Status: 2026-09-25. Companion docs: `PLAN.md` (research/rationale), `train_skeleton.py` (reference loss/model code; reuse it, don't re-derive).
Scope: user hums / whistles / sings (lyrics OK) into phone or web → server returns the song, asks ONE follow-up, or asks for a longer/clearer take.
**Server-first:** clients only record and upload audio. No on-device ML.

---
## 1. Decisions (fixed)
| Area | Decision |
|---|---|
| Encoder | `m-a-p/MERT-v1-95M` + pooling + 256-d projection head (fine-tuned). Ablation: OMAR-RQ `mtg-upf/omar-rq-multifeature-25hz-fsq` |
| Catalog | FMA + MTG-Jamendo (paper), lawfully owned files (demo), permission-gated previews only (D-009); 10 s chunks, 5 s hop; pgvector |
| Retrieval | kNN over chunks → group by song, score = best chunk → top-10 songs |
| UI | song title + artist first; player underneath starting at the matched chunk's `start_s` |
| Training | supervised contrastive (InfoNCE, same-song masking), AdamW; stage A real hums → stage B + synthetic → stage C + Google ideas (multi-singer alignment pairs, batch confidence loss) |
| Compute | GPU box (RunPod/Lambda/Vast): download, synth, train, embed_catalog, eval. App server: Postgres+pgvector (self-hosted, Supabase or Neon) + search API + website |
| Decision layer | one OpenRouter client (`OPENROUTER_API_KEY`) serving both Jev and a lightweight LLM |
| Clients | web (v1), Swift app (later, same API) |

## 3. Data contracts
All manifests are JSONL, all audio is mono float at 24 kHz after `audio.load()`, and all paths are relative to `$H2S_DATA`.

**songs.jsonl** (catalog metadata)
```json
{"song_id":"yt:dQw4w9WgXcQ","title":"...","artist":"...","source":"yt|fma|jamendo","audio_path":"catalog/yt/dQw4w9WgXcQ.opus","duration_s":212.4,"license":"personal|CC-BY-4.0|...","lyrics":null,"meta":{"year":1987,"lang":"en","genre":"pop","vocal":"male"}}
```
`song_id` is a stable string `<source>:<native_id>`. `meta` keys feed follow-up questions (§8); missing values are allowed.

**pairs.jsonl** (training/eval pairs)
```json
{"pair_id":"mirqbsh:00012","query_path":"queries/mirqbsh/00012.wav","qtype":"hum|whistle|sing","qsource":"real|synth_hum|synth_whistle|sep_vocal|aligned","song_id":"...","song_start_s":42.0,"song_dur_s":10.0,"split":"train|val|test","group":"mirqbsh"}
```
- `song_start_s` may be null (unknown alignment). The dataloader then samples a random chunk, which is a weak positive.
- **Split by song_id, never by recording.** `tests/` asserts there is no song_id overlap across splits.

**synth jobs** write to `queries/synth/<song_id>/<start>_<kind>.wav`, plus `f0/<song_id>.npz` (CREPE f0, confidence, rms @100 Hz) and `stems/<song_id>/vocals.wav`.

**Eval sets** (manifests in `data/eval/`), all split by song:
| Set | qtype | Refs | Notes |
|---|---|---|---|
| `mirqbsh_real` | hum/sing | real recordings of the 48 songs + ≥2000 distractors | all 48 songs excluded from training ("Jang Real" protocol, CHAD arXiv:2312.01092) |
| `mtgqbh` | sing | 118 songs + distractors | |
| `mlend_whistle` / `mlend_hum` | whistle / hum | 8 songs + distractors | all 8 songs held out |
| `humtrans_test` | hum | MIDI-synth or real audio | official split |
| `synth_sung_heldout` | sing | held-out catalog songs | separated vocals |
| `own_wild` | all | own catalog | 30-50 real phone/web recordings |

## 4. pgvector schema (`sql/001_init.sql`)
```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE TABLE songs (
  song_id TEXT PRIMARY KEY, title TEXT NOT NULL, artist TEXT, source TEXT NOT NULL,
  duration_s REAL, license TEXT, audio_url TEXT,            -- streamable URL for the player
  lyrics TEXT, meta JSONB NOT NULL DEFAULT '{}');
CREATE TABLE models (model_ver TEXT PRIMARY KEY, hf_repo TEXT, hf_revision TEXT, dim INT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT now(), is_active BOOLEAN DEFAULT false);
CREATE TABLE chunks (
  chunk_id BIGSERIAL PRIMARY KEY,
  song_id TEXT NOT NULL REFERENCES songs ON DELETE CASCADE,
  model_ver TEXT NOT NULL REFERENCES models,
  start_s REAL NOT NULL, dur_s REAL NOT NULL DEFAULT 10,
  emb vector(256) NOT NULL,
  UNIQUE (song_id, model_ver, start_s));
CREATE INDEX chunks_hnsw ON chunks USING hnsw (emb vector_cosine_ops) WITH (m=16, ef_construction=128);
CREATE INDEX ON chunks (model_ver);
CREATE TABLE sessions (session_id UUID PRIMARY KEY, created_at TIMESTAMPTZ DEFAULT now(),
  state JSONB NOT NULL);                                      -- decision-loop state (§8)
CREATE TABLE queries (query_id UUID PRIMARY KEY, session_id UUID REFERENCES sessions,
  ts TIMESTAMPTZ DEFAULT now(), qtype TEXT, qtype_conf REAL, duration_s REAL,
  emb vector(256), top10 JSONB, features JSONB, decision TEXT, llm_text TEXT,
  user_feedback TEXT, true_song_id TEXT);                    -- logging → Jev calibration + eval
```
**Search query** (song grouping by best chunk). Set `hnsw.ef_search` ≥ K.
```sql
WITH knn AS (SELECT song_id, start_s, 1-(emb <=> $1) AS sim FROM chunks
             WHERE model_ver=$2 ORDER BY emb <=> $1 LIMIT $3)          -- $3 = K, default 300
SELECT DISTINCT ON (song_id) song_id, start_s AS best_start_s, sim AS score FROM knn
ORDER BY song_id, sim DESC;          -- then in app: sort by score desc, take 10, join songs, add hits count
```
Re-rank hook: if `metadata_filter` is present (from a follow-up answer), apply it as a SQL filter on `songs.meta` and re-run with a larger K (e.g. 1000).

```jsonc
// DecisionResponse
{"session_id":"uuid","query_id":"uuid",
 "action":"show|ask_followup|ask_retry",
 "message":"text for the user (LLM-phrased for ask_*)",
 "results":[{"song_id":"...","title":"...","artist":"...","score":0.81,"best_start_s":55.0,"audio_url":"..."}], // top-10; UI shows [0] big for "show"
 "followup":{"question":"...","options":["1990s","2000s","not sure"]} | null,
 "debug":{"qtype":"hum","features":{...}}}   // only if DEBUG=1
```
- Server embedding runs on CPU for MERT-95M, or on an optional small GPU. Budget p95 < 2 s for a 10 s query plus kNN. Model loaded once at startup, `torch.inference_mode()`.
- Rate limiting and a max upload size are required. Delete uploaded audio after embedding unless `KEEP_QUERY_AUDIO=1`.

## 7. Training recipe
- **Model:** see `train_skeleton.py`. MERT-95M; layer-mix over the 12 layer outputs, captured with forward hooks (MERT's custom code on transformers 5.x returns `hidden_states=None`); AttnPool; MLP 768→512→256; L2-norm; learnable temperature (init 0.07); aux qtype head.
- **Inputs:** query 3-12 s random crop (pad/loop to 10 s batch length); song chunk 10 s aligned to `song_start_s` ± 1 s jitter.
- **Loss:** `L = InfoNCE_sym(q, s; same-song masked) + 0.1·CE(qtype) + λ_conf·L_conf`.
  - `L_conf` is the batch-level confidence loss, a Hum-to-Search idea. Per batch, let `p_i` = softmax prob of the positive in row i. Use `L_conf = mean_i(1 − p_i)^γ` with γ=2, a focal-style push of confidence toward 1 over the whole batch. Also log batch ECE. λ_conf ∈ {0, 0.1, 0.3} is an ablation.
- **Optimizer:** AdamW, wd 0.01, warmup 500, cosine; head LR 1e-3, backbone 1e-5; bf16; grad clip 1.0.
- **Stages:**
  - **A**: real only (MIR-QBSH train songs are excluded, since all 48 are test; HumTrans, MLEnd train portion only if songs are not in eval, CHAD hums). Backbone frozen, then top-6 layers unfrozen.
  - **B**: + synthetic. Batch mix roughly 35% real, 25% sep-vocal sung, 25% synth hum, 15% synth whistle. Sampler balances qtype and songs.
  - **C**: + `pairs_aligned.jsonl` (multi-singer alignment) + `L_conf`. Re-run `align_pairs.py` with the stage-B checkpoint first.
- **Augmentations:** pitch ±4 st, time-stretch 0.8-1.25, noise SNR 3-30 dB, RIR, phone-mic EQ, codec (opus/aac) round-trip, random gain.
- **Ablations (paper):** MERT vs OMAR-RQ vs CQT-ResNet18 baseline; ±synthetic kinds; ±aligned pairs; ±L_conf; chunk len 10 vs 6 s; frozen vs partial fine-tune.
- **Tracking:** W&B or TensorBoard; save `config.yaml`, git SHA and data-manifest hashes with every checkpoint.

## 8. Decision layer: Jev + llm via OpenRouter
**Client:** one OpenAI-compatible client, base URL `https://openrouter.ai/api/v1` (`/chat/completions`), header `Authorization: Bearer $OPENROUTER_API_KEY`. Two model slugs come from config:
- `JEV_MODEL`: **CONFIRM the exact slug with the user/TypeSafe before shipping.** On 2026-09-25 the OpenRouter models API listed `typesafe/jev-router` ("TypeSafe: Jev Router"; its description says it runs on Jev and links `~typesafe/jev-latest`). Which one to use for this role is unconfirmed.
- `LLM_MODEL`: any cheap, fast chat model on OpenRouter (user's choice; set it in `.env`).
- Both calls request JSON output. Timeout 8 s, 1 retry. On failure, fall back to the local threshold policy in `decide.yaml`.

**Features** (`decide/features.py`), computed from the top-10 (top-K for a few):
`s1..s10`, `gap12=s1-s2`, `gap15=s1-s5`, `entropy_top10` (softmax at the learned temperature), `hits_top1` (chunks of the top song in the K-list), `qtype`, `qtype_conf`, `duration_s`, `voiced_ratio` + `pitch_range_st` (from CREPE on the query), `turn` (loop count), `lyric_match` (optional Whisper branch, sing only), `n_candidates_after_filter`.

**Loop** (probabilistic-if style: Jev returns graded beliefs, not hard rules):
```python
llm = lambda prompt, **kw: openrouter.chat(model=cfg.LLM_MODEL, messages=prompt, **kw)   # variable wrapping OpenRouter
jev = lambda features, **kw: openrouter.chat(model=cfg.JEV_MODEL, messages=jev_prompt(features), response_format=JSON, **kw)

def decide(session, audio=None, answer=None):
    if audio is not None:
        q = embed(audio); session.add_query(q)                      # multi-turn: keep all query embeddings
    cands = search(session.query_emb(), filter=session.filters)     # top-10 songs, best chunk each
    f = features(cands, session)
    belief = jev(f)   # -> {"p_one_clear_winner": .., "p_few_close": .., "p_lost": .., "why": ".."}

    if feels(belief, "one clear winner", τ=cfg.T_SHOW):             # e.g. p_one_clear_winner ≥ 0.8 (per-qtype calibrated)
        return show(cands[0], alternatives=cands[1:10])

    elif feels(belief, "a few close", τ=cfg.T_FEW) and session.turn < cfg.MAX_TURNS:   # MAX_TURNS=2
        attr = best_split_attribute(cands[:5], keys=["decade","lang","vocal","genre","media_tie_in","remember_words"])
        question = llm(ask_one_followup_prompt(cands[:5], attr))    # phrase ONE question; must not reveal titles
        session.pending = attr
        return ask_followup(question, options=attr.options)
        # on /v1/answer: session.filters |= parse(answer, attr)  (llm may map free text → option)
        #                if answer == "remember_words": switch hint to singing; rerank; decide(session)

    else:                                                            # feels lost
        hint = retry_hint(f)   # e.g. too short / low voiced_ratio / whistle-low-score → "try humming the chorus ~10 s"
        return ask_retry(llm(ask_retry_prompt(hint, f["qtype"])))
```
Rules:
- The LLM never picks the song. It only phrases text and maps a free-text answer to an option.
- Jev gets numeric features only (no audio).
- Log every decision to `queries` for calibration.
- `feels(belief, label, τ)` = `belief[label] ≥ τ[qtype]`. Thresholds are fit by `calibrate_jev.py` to hit a target precision for "show" (default 0.9) on val.

## 10. Evaluation
- Per eval set **and per qtype (hum / whistle / sing)**: Top-1, Top-3, Top-10, MRR. Production will group chunks by song (best chunk); the current eval does not chunk: each reference is one clip, its first 10 s, and a song with several reference clips scores its best clip. Every set also reports a `targets_only` line (its own references, no distractors). HumTrans renders are never distractors (D-010).
- Decision layer: show-precision, answer rate, follow-up rate, retry rate, success within ≤2 turns, ECE; plus p50/p95 latency.
- Baselines to report next to ours: CHAD Top-10 on MIR-QBSH (MIDI refs 0.921; Jang Real 0.868; MTG-QBH 0.883) and ACRCloud MIREX 0.990 (numbers from arXiv:2312.01092). Numbers are only comparable when the protocol matches.
- `eval/report.py` emits `paper/tables/*.tex` + `runs/<name>/report.json`.
